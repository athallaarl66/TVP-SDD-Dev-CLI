Implement one user story scenario (numbered by PRD order) from the breakdown files using the TVP-SDD-Dev CLI workflow.

## What This Skill Does

When invoked, this skill will:
1. Take two inputs: feature name and scenario number
2. Locate the scenario's breakdown files: `docs/production/<feature>/<num>-*-{prod,tech,design,testing}.md`
3. Read all four files, which carry the user story (As a / I want / So that), acceptance criteria, API and database specs, design guidance, and testing scenarios
4. Optionally read `docs/features/<feature>-technical.md` for high-level architecture context
5. Implement the single scenario's user story, verifying work against its acceptance criteria and testing files

## When to Use

Use this skill when you need to:
- Implement one specific user acceptance scenario from a PRD
- Turn scenario-level documentation (prod/tech/design/testing) into working code
- Implement scenarios one at a time, in PRD order

## How to Use

Provide the feature name and the scenario number:
```
Feature name: user-authentication
Scenario number: 01
```

The scenario number matches the `<num>` prefix in the breakdown filenames, which follows the user-story order in the PRD.

## File Lookup

For feature `user-authentication` and scenario `01`, the skill reads:

```
docs/production/user-authentication/
├── user-authentication-01-<story-slug>-prod.md      → user story + acceptance criteria
├── user-authentication-01-<story-slug>-tech.md      → API, DB, permissions, security
├── user-authentication-01-<story-slug>-design.md    → wireframe, UI components
└── user-authentication-01-<story-slug>-testing.md   → test cases (Given/When/Then)
```

Optionally reads `docs/features/user-authentication-technical.md` for global architecture context when present.

## Implementation Rules

1. Implement **only** the requested scenario number. Never touch files belonging to other scenario numbers.
2. Implement every acceptance criterion listed in the `-prod.md` file.
3. Follow the API, database, and permission specs in matching `-tech.md` and the design guidance in `-design.md`.
4. Verify the implementation against the test cases in `-testing.md`.

## After Implementation

After the scenario is implemented, you should:
1. Run the matching test scenario(s) from the `-testing.md` file
2. Report which acceptance criteria are met
3. Suggest the next scenario number to implement

## Error Handling

- No breakdown files match `docs/production/<feature>/<num>-*-*.md` → report the expected path and tell the user to run `sdd-gen /breakdown-task <prd-file> <feature>` first
- Multiple files match (slug collision) → pick the file whose `User Story` header matches the requested scenario number
- `docs/features/<feature>-technical.md` missing → proceed without global context (it is optional)

## Notes

- This is the third step in the documentation workflow, after PRD generation and breakdown
- One invocation implements exactly one scenario
- The breakdown files must be filled in with scenario-specific details before implementation
